# Agent-Based Modelling of Compute Placement for Latency- and Throughput-Aware Mobile Edge Computing

Code accompanying the dissertation *"Agent-Based Modelling of Compute Placement for Latency- and
Throughput-Aware Mobile Edge Computing"* (Marie Courtine, Trinity College Dublin, 2026).

An agent-based mmWave 5G network simulator extended with an application-aware edge compute (CR:
"Compute Resource") placement layer. A Q-learning agent decides, at every simulation step, which
base stations host edge compute resources, and is compared against four baselines (no compute,
random, static, and a clairvoyant greedy oracle) across three deployment scenarios of increasing
density. See the dissertation for the full system model, methodology, and results; this README
documents the code that produced them.

## Status of this repository

Everything needed to reproduce **Chapters 3-7** (system model, MDP formulation, baselines,
Experiments A-D, and Section 7.8's robustness-at-scale runs) is complete, runnable, and has been
executed end to end.

- The raw outputs of that pipeline (CSV logs, trained Q-tables, figures behind every table and
  figure in Chapter 7) are committed under
  [`results/Chapter7_complete_data_by_scenario/`](results/Chapter7_complete_data_by_scenario/), one
  folder per scenario/condition combination. See [`results/README.txt`](results/README.txt) for the
  exact layout and what was pruned from it.
- `output/` itself (see [Output layout](#output-layout)) stays gitignored and is regenerated by
  re-running the scripts below. A static copy is committed under `results/` instead, since a full
  run takes real compute time (thousands of training steps × 3 scenarios × up to 20 eval seeds per
  condition).
- **Section 7.8** ("Robustness at Larger Network Scale") has been run to completion for both
  Urban-N12 (3 train seeds × 2 admission-policy conditions) and Urban-XL (3 train seeds ×
  2 reward-shaping variants). Results are committed under [`results/N12/`](results/N12/) (Table
  7.13-style paired-diff CSVs and figures) and [`results/Urban-XL/`](results/Urban-XL/) (Tables
  7.14/7.15: training diagnostics and RL-vs-baselines paired difference). Commands are under
  [Reproducing the dissertation's results](#reproducing-the-dissertations-results).

Everything in `experiments/` and `analysis/` is a standalone script - nothing outside `main.py`,
`agents/`, `configs/`, `simulation/` and `plots/` is imported by anything else. **All commands below
are meant to be run from this directory** (`abm_communication_networks/`, the one this README is in).

## Scenario configs

| Config | Dissertation name | Users | Base stations (N) | CR slots (K) | Mobility | App mix (AR/VR·stream·best-effort) |
|---|---|---|---|---|---|---|
| `configs/urban_light.py` | Urban-Light | 20 | 3 | 2 | high | 20·50·30 |
| `configs/urban_medium.py` | Urban-Medium | 30 | 4 | 2 | low | 40·40·20 |
| `configs/urban_dense.py` | Urban-Dense | 40 | 6 | 3 | low | 50·40·10 |
| `configs/urban_controlled.py` | Urban-Controlled | 30 | 4 | 2 | high | 40·40·20 |
| `configs/urban_xl_lambda0.py` | Urban-XL (λ=0) | 80 | 8 | 4 | low | 50·40·10 |
| `configs/urban_xl_lambda01.py` | Urban-XL (λ=0.1) | 80 | 8 | 4 | low | 50·40·10 |
| `configs/urban_large_N12.py` | Urban-N12 | 80 | 12 | 6 | low | 50·40·10 |
| `configs/default.py` | (development default, all-best-effort) | 20 | 4 | 2 | high | 0·0·100 |

`urban_controlled` is identical to `urban_medium` except for mobility - it isolates the effect of
mobility from load (§7.5.2). The two `urban_xl_lambda*` configs are identical except for
`reward_shaping_lambda` (§7.6/§7.8).

## Installation

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Requires Python 3.10+ (developed and tested on 3.11). `pygame` is only needed for the interactive
viewer (`main.py`); every other script is headless.

## Quickstart

**1. Watch the simulator run interactively** (random/no-CR policy, no training):

```bash
python main.py
```

**2. Run the automated tests:**

```bash
python -m pytest tests/ -v
```

**3. Reproduce one scenario end to end** (the low-level building block everything else wraps):

```bash
# Train the relay-node positioning agent, then freeze it
python experiments/run_experiment.py --scenario urban_medium --mode train_rn \
    --steps 1000 --rn-qtable models/rn.pkl

# Train the CR placement agent against the frozen RN policy
python experiments/run_experiment.py --scenario urban_medium --mode train_cr \
    --steps 2000 --rn-qtable models/rn.pkl --cr-qtable models/cr_qtable.pkl

# Evaluate the trained agent (20 seeds would be run individually, --seed 0..19)
python experiments/run_experiment.py --scenario urban_medium --mode eval \
    --strategy rl --rn-qtable models/rn.pkl --cr-qtable models/cr_qtable.pkl --seed 0

# Evaluate a baseline for comparison (no training needed)
python experiments/run_experiment.py --scenario urban_medium --mode eval \
    --strategy static --rn-qtable models/rn.pkl --seed 0
```

Run `python experiments/run_experiment.py --help` for the full flag reference, including
`--cr-admission-policy`, `--radio-allocation` (the Experiment D factorial switches) and
`--migration-mode` (the migration-cost models of §5.3.3/§9.2.2).

## Reproducing the dissertation's results

**Experiment A** (all baselines vs. the trained agent, all three main scenarios - the source of
Table 7.3) and the training/eval pipeline behind it:

```bash
# Full pipeline for the three main scenarios: trains RN + CR agents, evaluates
# all 5 strategies over 20 seeds, and writes the per-scenario figures.
python experiments/generate_results.py --seeds 20

# Statistics + figures from the resulting logs/ directory of a single run
python analysis/run_analysis.py --logs-dir output/output-urban_medium/logs

# Paired-difference test, RL vs. each baseline (Table 7.8)
python analysis/paired_diff_experimentA.py
```

**Experiment B** (satisfaction & CR utilisation vs. scenario density, Table 7.5) and **Experiment C**
(mobility vs. migration demand, §7.5, Tables 7.6-7.7):

```bash
python analysis/analyze_experiment_B.py
python analysis/analyze_experiment_C.py               # naive comparison (§7.5.1)
python analysis/analyze_experiment_C_controlled.py     # controlled comparison (§7.5.2)
```

**Experiment D** (the 2×2 admission-policy × radio-allocation factorial, §7.7):

```bash
# Retrain and evaluate the three non-baseline conditions (M1, M2, M3)
python experiments/generate_results.py --seeds 20 --cr-admission-policy priority --radio-allocation equal_share    # M1
python experiments/generate_results.py --seeds 20 --cr-admission-policy fcfs     --radio-allocation proportional   # M2
python experiments/generate_results.py --seeds 20 --cr-admission-policy priority --radio-allocation proportional   # M3

# 2x2 factorial effect decomposition (Table 7.11), reads all four conditions
python analysis/factorial_analysis.py
```

`compare_admission_policy.py` and `compare_strategies_urban_medium.py` are earlier, narrower
versions of the same comparisons kept for reference and quick smoke-testing; the scripts above are
the ones used for the numbers reported in the dissertation.

**Migration-cost models** (§5.3.3/§9.2.2 - evaluated on top of already-trained Q-tables, no retraining):

```bash
python experiments/compare_migration_cost.py --scenarios urban_medium urban_dense
```

**Urban-N12** (§7.8.2, Table 7.13):

```bash
python experiments/run_large_n12_experiments.py
python experiments/verify_large_n12_models.py   # sanity-checks the resulting Q-tables
```

**Urban-XL** (§7.8.3/§7.8.4, Tables 7.14-7.15):

```bash
python experiments/run_urban_xl_train.py                                # train, skip-if-exists
python experiments/run_urban_xl_eval.py                                 # eval, all baselines + RL (tseed0)
python experiments/run_urban_xl_eval_tseed.py 0   # RL only, urban_xl_lambda0, per training seed
python experiments/run_urban_xl_eval_tseed.py 1   # (repeat with 1, 2; VARIANT is hardcoded in the
python experiments/run_urban_xl_eval_tseed.py 2   #  script, edit it to target lambda01 instead)
python analysis/analyze_urban_xl.py               # Tables 7.14-7.15 from the resulting logs
```

See [EXPERIMENTS.md](EXPERIMENTS.md) for what each of these runs does and why, stage by stage.

## Output layout

Every script above writes into a gitignored `output/` (and, for `run_experiment.py`/`main.py`,
`models/`/`logs/`) directory at the project root, structured as:

```
output/
  output-<scenario>/                # M0 (default fcfs + equal_share)
  output-<scenario>__M1/             # priority + equal_share
  output-<scenario>__M2/             # fcfs + proportional
  output-<scenario>__M3/             # priority + proportional
    models/       rn_1.pkl, rn_2.pkl, ..., cr_qtable.pkl
    logs/
      train_rn/   rn_reward.csv, rn{id}_learning.csv
      train_cr/   cr_reward.csv, cr_delta_q.csv
      eval/{trained|no_cr|random|static|exhaustive_greedy}/s{seed}/
                  satisfaction_summary.csv, satisfaction_users.csv,
                  cr_utilization.csv, hop_counts.csv
    fig1_training_curves.png … fig5_satisfaction_timeseries.png
```

This directory is intentionally not committed (see `.gitignore`): it is fully regenerated by the
scripts above, given a fixed seed, byte-for-byte (verified by `tests/test_simulation.py`).

## Testing

```bash
python -m pytest tests/ -v
```

Two tests: a smoke test (simulator runs 10 steps without error) and a reproducibility test (two runs
with the same seed produce identical `hop_counts.csv` output - the guarantee the paired-seed
experimental design in Chapter 6 relies on).
